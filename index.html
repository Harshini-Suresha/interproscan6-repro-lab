Reproducing InterProScan 6

InterProScan 6 annotates protein sequences with domains, families and functional sites by combining many member-database methods in one Nextflow workflow. This site rebuilds a small, honest slice of that job in your browser and gives you the commands to run the real pipeline.

AnnotateScan proteins for sequence motifs and get TSV output.
CompareMeasure coverage and agreement between two annotation files.
BenchmarkTime the scanner and check that every configuration gives identical output.
Real pipelineCommands, timing wrapper and the configuration matrix.

What is and is not implemented

The browser scanner is a miniature, not InterProScan. It uses six PROSITE-style patterns (written from memory, so verify them against PROSITE) and has no HMMs, no InterPro entries and no database integration. The real InterProScan 6 needs tens of gigabytes of member-database data and cannot run in a web page. Results on the Annotate and Benchmark pages describe this miniature only, and the demo proteins are synthetic.

The four goals from the project brief map to the site: reproduce annotation (Annotate, Real pipeline), compare with reference records (Compare), measure runtime, memory and coverage (Benchmark), and test reproducibility across configurations (Benchmark, Real pipeline).

Annotate

Paste a protein FASTA or generate a synthetic set with planted motifs, then scan.

Compare

Paste or load two TSV files (this site’s output or real InterProScan output). Matching uses column 1 (protein) plus the signature in column 5 or the InterPro entry in column 12. Nothing is uploaded.

Agreement is the Jaccard overlap of (protein, accession) pairs. Coverage is the share of input proteins with at least one annotation.

Benchmark

Runs the same scan under five configurations that change chunk size and input order, then checks whether the sorted output is byte-identical. Time is wall-clock in this browser; memory uses the heap counter where the browser exposes one (Chromium).

Real pipeline

Confirm flag names and database setup in the official repository. The commands below follow its README for version 6.0.1. You need Nextflow 25.10.4 or later and a container engine; the data files download by themselves into --datadir on the first run. Pin both the pipeline version and the InterPro release.

First, the built-in test

nextflow run ebi-pf-team/interproscan6 -r 6.0.1 -profile docker,test --datadir data --interpro 108.0

Then your own proteins

nextflow run ebi-pf-team/interproscan6 \
  -r 6.0.1 \
  -profile docker \
  --input data/proteins.faa \
  --datadir data \
  --interpro 108.0

Results are written to the working directory, named after the input (for example proteins.faa.tsv, plus JSON, XML and GFF3 files). Check that 108.0 is still available; the paper used it.

Timing wrapper

#!/usr/bin/env bash
name=$1; shift; mkdir -p runs/$name; cd runs/$name
/usr/bin/time -v -o time.txt \
  nextflow run ebi-pf-team/interproscan6 -r 6.0.1 -profile docker \
  --input ../../data/proteins.faa --datadir ../../data --interpro 108.0 "$@"
grep -E "Elapsed|Maximum resident" time.txt

Methodology in plain words

The question

InterProScan 6 reads a protein’s amino-acid sequence and says what it probably does, by finding known domains, families and functional sites in it. This project asks four simple things. Can we run it ourselves and get sensible annotations? Do those annotations match trusted reference records? How much time and memory does it need? And does it give the same answer every time, however we set it up?

What you need

  • A small set of protein sequences in FASTA format, 50 to 200 to start. Note where they came from: [dataset name and source].
  • Reference records for the same proteins, such as the UniProt or InterPro entries for each one: [reference source and download date].
  • The pipeline version [version] and the database release [release], written down before you start.
  • A computer: [CPU model, cores, RAM, operating system]. A CPU is enough, but the database download is big, so check free disk space first.

Steps

  1. Pick the proteins and save them as one FASTA file. Do not change it afterwards.
  2. Install Nextflow and a container engine, then download the pipeline databases as the official instructions describe.
  3. Run the pipeline’s own test first, to prove the setup works before using your data.
  4. Run your FASTA once as the baseline, wrapped in the timing script so time and memory are recorded.
  5. Compare the baseline output with the reference records on the Compare page, and note coverage and agreement.
  6. Repeat the run changing one thing at a time: the container engine, the number of CPUs, then a second run with identical settings. Record time and memory each time.
  7. Check whether the outputs are identical (see below), and log everything on the Your results page.

Checking reproducibility

Two outputs can be the same in substance but differ in row order or in the date column. So remove the date, sort the rows, then make a fingerprint. Identical fingerprints mean identical annotations. Check your file’s columns first, since the date is normally column 11.

cut -f1-10,12-15 runs/baseline/proteins.faa.tsv | sort | sha256sum

Do this for every run and paste the first characters of each fingerprint into the results table. If two runs with the same inputs give different fingerprints, use the Compare page to see exactly which matches differ.

Reading the results fairly

  • Agreement with a reference tells you how similar the two are, not which one is right. The reference can be incomplete or older.
  • Changing the database release will change results for good reasons. Report that apart from reproducibility problems.
  • Time depends on the machine, so always state the hardware.
  • A small protein set gives rough numbers. Say how many proteins you used.
  • The browser Annotate and Benchmark pages are a miniature with six patterns. Do not report their numbers as InterProScan results.

Real data from the paper

These are the published results of InterProScan 6, copied from Blum M, Hobbs E, Florentino L, Bateman A. InterProScan 6: a modern large-scale protein function annotation pipeline. Bioinformatics Advances 2026; 6(1): vbag141. doi:10.1093/bioadv/vbag141 (open access, CC BY 4.0). I did not run anything to get them.

How the paper measured it

  • Nine UniProt reference proteomes (release 2025_04, one protein sequence per gene).
  • InterProScan 5.77-108.0 against InterProScan 6.0.0 run through Nextflow with Singularity, both using InterPro release 108.0.
  • EMBL-EBI Slurm cluster, 8 CPU cores per task (Intel Xeon Gold 6252), 90 GB memory requested per job.
  • Median of five runs. Times are full pipeline runs and exclude one-time data downloads. Run-to-run spread (MAD/median) was under 6%.

Using this for your reproduction

  • The two smallest proteomes are the realistic ones to repeat: E. coli (UP000000625, 4,402 sequences, 39 min in the paper) and M. tuberculosis (UP000001584, 3,996 sequences, 44 min). Download them from UniProt using the exact IDs above.
  • Your hardware will differ, so compare ratios (IPS 6 with and without match lookup) rather than raw minutes, and state your CPU count.
  • Use the same InterPro release as the paper (108.0) when checking annotations, so database changes do not confuse the comparison.
  • The paper also lists every individual benchmark run in its Supplementary Table 1 (an xlsx file on the journal page), which I could not download.

Machine-readable copies of these tables are in the zip under results/paper_*.csv.
